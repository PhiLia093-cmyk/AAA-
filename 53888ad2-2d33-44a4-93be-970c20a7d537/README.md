## 一、项目背景与目标

计算机使用二进制表示和传输数据。字符经过字符编码后变成二进制位；传输时，线路中的干扰可能造成某些位发生变化。奇偶校验通过增加一个校验位，让接收端可以检查数据帧中的错误。

本小组以 ASCII 字符为例，整理字符编码、校验位生成、数据发送和接收检查的完整过程。目标是用简洁的计算和表格说明每一步，让读者能够跟随数据从发送端到接收端。

## 二、项目内容与功能要求

1. **字符编码：** 将一个 ASCII 字符转换为对应的十进制码和 7 位二进制数据。
2. **校验位生成：** 分别说明偶校验和奇校验如何根据数据中 `1` 的数量确定校验位。
3. **发送过程：** 将 7 位 ASCII 数据与 1 位校验位组合为 8 位数据帧，并按位说明发送顺序。
4. **接收检查：** 接收端统计完整数据帧中 `1` 的数量，并判断奇偶性是否符合约定。
5. **错误示例：** 演示一位数据发生翻转时，接收端如何发现奇偶性不符。
6. **能力说明：** 说明奇偶校验能够检测什么，以及不能定位或修复错误的限制。

## 三、方案设计与原理

### 3.1 数据格式

本示例采用 7 位 ASCII 数据和 1 位奇偶校验位。校验位放在数据位之后：

```text
数据帧 = b6 b5 b4 b3 b2 b1 b0 P
```

其中 `b6` 是最高位，`b0` 是最低位，`P` 是校验位。

### 3.2 校验规则

- **偶校验：** 选择 `P`，使整帧中 `1` 的总数为偶数。
- **奇校验：** 选择 `P`，使整帧中 `1` 的总数为奇数。

发送端和接收端必须使用相同的校验规则，否则即使数据没有发生变化，接收检查也可能失败。

## 四、发送与接收演示

### 4.1 字符转换为 ASCII

选择字符 `A`。它的 ASCII 十进制值是 **65**，转换成 7 位二进制为 `1000001`。

| 数据位 | b6 | b5 | b4 | b3 | b2 | b1 | b0 |
|:---|---:|---:|---:|---:|---:|---:|---:|
| 位权 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
| 数据位的值 | 1 | 0 | 0 | 0 | 0 | 0 | 1 |
| 位权贡献 | 64 | 0 | 0 | 0 | 0 | 0 | 1 |

计算结果：`64 + 1 = 65`。数据中共有 **2 个 `1`**。

### 4.2 发送端添加校验位

以偶校验为例，数据中已有 2 个 `1`，已经是偶数，因此 `P = 0`。

```text
ASCII 数据：1000001
校验位 P：        0
偶校验帧：10000010
```

验证：`2 + 0 = 2`，整帧包含偶数个 `1`。

若改用奇校验，则需要 `P = 1`：

```text
ASCII 数据：1000001
校验位 P：        1
奇校验帧：10000011
```

验证：`2 + 1 = 3`，整帧包含奇数个 `1`。

### 4.3 数据逐位发送

以下按偶校验帧 `10000010` 演示。发送顺序为从左到右，接收端逐位收集：

| 发送次序 | 位名称 | 发送位 | 接收端当前内容 |
|---:|:---|:---:|:---|
| 1 | b6 | 1 | `1·······` |
| 2 | b5 | 0 | `10······` |
| 3 | b4 | 0 | `100·····` |
| 4 | b3 | 0 | `1000····` |
| 5 | b2 | 0 | `10000···` |
| 6 | b1 | 0 | `100000··` |
| 7 | b0 | 1 | `1000001·` |
| 8 | P | 0 | `10000010` |

### 4.4 接收端检查数据帧

接收端收齐 8 位后，按事先约定的偶校验规则统计 `1` 的数量：

```text
收到的数据帧：10000010
1 的数量：    2
偶校验要求：  1 的数量为偶数
检查结果：    通过
```

检查通过后，接收端去掉最后的校验位 `P`，得到 ASCII 数据 `1000001`，即十进制 **65**，还原为字符 `A`。

### 4.5 发生传输错误时

假设数据位 b6 在传输中从 `1` 翻转为 `0`：

```text
发送的数据帧：10000010
接收的数据帧：00000010
```

接收帧中只有 1 个 `1`，不符合偶校验要求，因此接收端报告**奇偶校验失败，检测到传输错误**。

## 五、测试与结果

| 测试场景 | 发送帧 | 接收端统计 | 预期结果 |
|:---|:---:|:---|:---|
| 偶校验，数据未变化 | `10000010` | 2 个 `1`，为偶数 | 校验通过 |
| 奇校验，数据未变化 | `10000011` | 3 个 `1`，为奇数 | 校验通过 |
| 偶校验，b6 翻转 | `00000010` | 1 个 `1`，为奇数 | 检测到错误 |

## 六、项目结论与局限

本示例完成了从 ASCII 编码、校验位生成到数据接收检查的说明。奇偶校验实现简单，能发现**奇数个位**发生翻转的情况，但也有以下限制：

- 校验失败时只能说明数据可能发生错误，不能指出具体哪一位出错。
- 奇偶校验不能自动修复错误。
- 如果有偶数个位同时翻转，奇偶性可能仍符合要求，错误可能无法被发现。

因此，奇偶校验适合用于简单的错误检测演示，不能替代更可靠的差错检测与纠正方法。
